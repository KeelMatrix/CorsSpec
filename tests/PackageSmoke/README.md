# Package consumer smoke test

This non-packable project references `KeelMatrix.CorsSpec` only through the built package. `scripts/Invoke-PackageSmoke.ps1` restores it against an isolated local package feed and disposable NuGet cache/output directories, then runs simple allowed/denied requests plus a real-host check that an explicit `Accept` scenario value overrides an unsafe same-named client default and is serialized without an unnecessary preflight. It also runs an allowed custom-method/requested-header browser-style preflight (including `Accept: */*`) and a denied preflight that sends no actual request against a real ASP.NET Core `TestServer` pipeline.

Clients use `CorsTransport.CreateClient` over direct TestHost handlers. The smoke checks names-only uncertainty and unsupported TestHost formatting changes and canonical content-header boundaries as well as ordinary allowed/denied results. No project reference or sibling source is available to the consumer.

`FirstResponseProbes` also exercises the first-response value snapshot over direct TestHost and real loopback networking. It covers CORS metadata additions/removals/replacements, status and request-provenance rewriting, unchanged controls, both expectations and preflight paths, and response/content/handler cleanup after success, failure and cancellation. The integration project compiles the same probes against its source reference; this consumer compiles them against the built package.

`ClientBoundaryProbes` creates shared clients over direct TestServer/WebApplicationFactory handlers and both BCL network handlers, including clean and configured delegating pipelines. It verifies ordinary traffic before/after verification, simple/preflighted operations and both expectations, isolated preflights, actual defaults/credentials and caller/factory ownership. Already-created ordinary clients and opaque terminals must return actionable `UnsupportedTransport` before verification host I/O. Controls exercise factory redirect/cookie defaults and `ConfigureClient` settings, which do not transfer to direct handlers. The ASP.NET testing dependencies remain in the consumer; the shipping package gains none and supplies no host-observer adapter.
